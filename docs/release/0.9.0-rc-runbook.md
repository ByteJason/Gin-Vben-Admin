# 0.9.0-rc 发布运行手册

本文用于隔离环境的候选版本部署、升级和回滚。生产环境执行前，请由部署负责人根据实际备份、网络、密钥和容量条件复核命令。

## 1. 验证发布包

在解压目录执行：

```text
shasum -a 256 -c SHA256SUMS
```

归档包含 API/嵌入式服务端二进制、`server.example.yaml`、`LICENSE` 和 `NOTICE`。当前候选只生成本地归档和 provenance，不自动推送镜像、注册表或签名服务。

## 2. 启动前检查

1. 复制 `server.example.yaml` 为本地配置，或使用环境变量覆盖连接信息。
2. 确认 MySQL 或 PostgreSQL 数据库、Redis 地址和应用端口可达。
3. 确认根 `.env` 与运行时密钥权限为 0600；不要把密码写入日志或命令行参数。
4. 先执行 `status`，确认数据库不是 dirty 状态。

## 3. 迁移与启动

```text
go -C server run ./cmd/migrate status --config configs/server.yaml
go -C server run ./cmd/migrate up --config configs/server.yaml
go -C server run ./cmd/api --config configs/server.yaml
```

启动后检查：

```text
curl -fsS http://127.0.0.1:8080/health/live
curl -fsS http://127.0.0.1:8080/health/ready
```

API 不会自动执行迁移；迁移失败时保持原状态并保存日志。

## 4. 备份、升级和回滚

升级前先使用本地备份服务生成带 SHA-256 的备份工件，并记录数据库驱动、版本和时间。只在可丢弃或已确认可恢复的环境执行 down 演练：

```text
node scripts/migration-smoke.mjs --check
MIGRATION_SMOKE_INTEGRATION=1 MIGRATION_SMOKE_MYSQL_DSN=... MIGRATION_SMOKE_POSTGRES_DSN=... node scripts/migration-smoke.mjs --integration
```

应用回滚顺序为：停止新进程 → 确认备份可读 → 恢复兼容的数据库版本 → 启动旧二进制 → 检查 `health/ready` → 保留事件记录。不要在未确认备份的情况下执行破坏性 down。

## 5. 可选观测 profile

默认 Compose 不启动采集器。需要本地观测时，在隔离环境叠加：

```text
node scripts/prepare-runtime-compose.mjs
docker compose -f .runtime/compose/observability.yaml --profile observability up -d
```

Prometheus 抓取 `/metrics`，OTLP Collector 接收 HTTP/gRPC，Grafana 提供只读仪表盘，Alertmanager 将五类规则发送到本地 webhook fixture。应用管理端可配置外部采集地址、TLS 和脱敏凭据；本 profile 不包含远程 SaaS 地址。

## 6. 当前验收边界

- MySQL/PostgreSQL/Redis 的本地单机与隔离 HA 验收已有记录；生产容量、跨地域 RPO/RTO 不由本地结果推断。
- 远程对象存储尚未连接或写入；获得资源后再进行 MinIO/S3 验收。
- 注册表发布、OIDC 无密钥签名和镜像 provenance 需要部署方提供身份与目标后单独执行。

## 7. 故障处理

- `health/live` 失败：检查进程、端口和配置路径。
- `health/ready` 失败：检查数据库/Redis 连通性和凭据，查看脱敏日志。
- 迁移 dirty：停止应用，保留状态输出和备份，按迁移文件的 down/修复手册处理，不强行重复 up。
- 观测不可达：关闭对应开关或修正外部地址；导出失败应降级记录并保留 `app_observability_export_dropped_total` 指标。
