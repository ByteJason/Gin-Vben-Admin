# Gin-Vben-Admin 1.0.0-dev 全功能手工验收手册

> 基线：当前 `main`（本轮起点 `0a8182f`，2026-08-25）<br>
> 适用范围：从新 clone、首次安装、登录，到所有产品菜单、边界数据、隔离、部署与回滚的手工验收。<br>
> 本文是**执行清单**，不是已执行通过报告；每条用例必须填写实际结果和证据后才可判定。

## 1. 如何使用这份手册

### 1.1 状态标记

| 标记 | 含义 | 如何判定 |
|---|---|---|
| `P` | 本版应通过 | 实际结果、HTTP 状态、持久化结果均符合预期 |
| `C` | 条件验收 | 需要 SMTP、PostgreSQL、对象存储、Prometheus 等外部夹具 |
| `R` | 当前预期红灯 | 本版已有明确缺口；记录证据并进入版本门禁 |
| `D` | 模板/演示页 | 只做视觉、路由和交互冒烟，不当作业务数据能力 |

结果只写 `PASS / FAIL / BLOCKED / NOT-RUN`。`BLOCKED` 必须附阻塞条件；`FAIL` 必须附 `requestId`、截图或日志。

为每轮创建目录（目录保持在可丢弃 clone 外，且不提交凭据）：

每条用例记录：

```text
实际结果：

```

## 2. 总流程与停止条件

按顺序执行，前一阶段的关键门禁通过后再进入下一阶段：

1. 环境与仓库基线。
2. Docker 一键部署冒烟。
3. 可丢弃 clone 中执行首次安装。
4. 登录、会话和全局框架。
5. 用户、角色、菜单、权限和范围隔离。
6. 设置、审计、文件、字典、邮件、任务、导入导出、监控。
7. 三套 UI 等价、响应式、键盘和双语。
8. 数据持久性、故障降级、升级和回滚。
9. 汇总发布门禁。

立即暂停并写 checkpoint 的情形：生产环境写入、非可丢弃数据删除、未确认的数据库降级、凭据出现在响应/日志/HAR、租户越权、回滚校验失败、预期外的迁移变更。

## 3. 阶段 0：从 clone 建立验收基线

### UAT-ENV-001 新 clone 和工具版本（P）

```bash
git clone REPOSITORY_URL Gin-Vben-Admin-UAT
cd Gin-Vben-Admin-UAT
git status --short --branch
git rev-parse HEAD
node --version
corepack pnpm --version
go version
docker version
docker compose version
```

预期：

- 工作树干净，提交号已写入 `00-environment.txt`。
- Node.js 为 `^22.18.0 || ^24.12.0`，pnpm 为 `11.16.0`，Go 为 `>=1.24`，Docker Compose 为 v2。
- 任一工具版本不满足时，本轮结果为 `BLOCKED`，先修正验收机环境。

### UAT-ENV-002 静态自检与依赖安装（P）

```bash
node ./scripts/bootstrap.mjs --check
go -C server mod download
node scripts/build.mjs --mode embedded --ui antd --check
cd admin
pnpm run init -- --check
pnpm run dev
cd ..
```

预期：`BOOTSTRAP_CHECK_OK`、`BUILD_CHECK_OK`，init 输出 `INIT_STATE=pristine`、`INIT_NEXT=CHECK_COMPLETE`；尚未初始化的 `pnpm run dev` 以退出码 2 输出 `INIT_ERROR=PROFILE_REQUIRED`，锁文件未变化。本流程只在可丢弃 clone 内执行，避免本机 profile 和验收状态污染开发工作树；三套模板不得移动或删除。

### UAT-ENV-003 非法引导参数（P）

分别执行：

```bash
node ./scripts/bootstrap.mjs --ui unknown --database mysql --skip-install
node ./scripts/bootstrap.mjs --ui antd --database sqlite --skip-install
node scripts/build.mjs --mode unknown --ui antd --check
cd admin
pnpm run init -- --ui unknown --confirm-cleanup --no-open
pnpm run init -- --check --port 0
```

预期：均以非 0 退出，输出稳定错误，未生成半成品配置。

## 4. 阶段 1：Docker 已安装部署与基础设施冒烟

源码首次安装不使用本阶段代替：全新 clone 必须进入阶段 2，通过普通 Go API 的 `/install` 完成
UI、数据库、Redis 和管理员安装。Docker 路径面向已经由部署平台提供持久后端安装标记与运行配置的
环境；仓库当前 Compose 样例没有挂载 `.runtime/install/.installed`，因此默认命令只验收镜像构建、
迁移和基础设施拓扑，首次安装/管理员登录继续作为独立红灯记录。

### UAT-DEPLOY-001 构建并启动（P：基础设施；R：首次登录闭环）

```bash
docker compose -f deploy/docker-compose.yml config --quiet
ADMIN_UI=antd docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml run --rm migrate status
curl -i http://127.0.0.1:8080/health/live
curl -i http://127.0.0.1:8080/health/ready
curl -i http://127.0.0.1:8080/api/admin/v1/ping
```

浏览器打开 `http://127.0.0.1:5173`，记录首页、Network 和 Console。

预期：

- MySQL、Redis 健康；`migrate` 成功结束；server、admin 运行；live、ready 返回 200。
- **当前红灯**：安装 marker 不存在时，ping 被安装门禁拦截并返回 423；这符合后端门禁，但不构成已安装部署。
- **当前红灯**：Compose 默认 `AUTH_ENABLED=false`，没有初始管理员输入；admin Nginx 未转发 `/install/`，server 镜像也未带 `embed` 安装资源。因此“单机 Compose → 首次安装 → 管理员登录”尚未形成闭环。将基础设施冒烟和用户首登分别判定，不把前者代替后者。

### UAT-DEPLOY-002 重启和卷持久性（P）

1. 记录 `docker compose ps` 和卷名。
2. 执行 `docker compose stop`，再执行 `docker compose start`。
3. 重查 health、ping、迁移状态。
4. 保留命名卷时，数据库和 Redis 数据应保留。

只在可丢弃项目执行最终清理：

```bash
docker compose -f deploy/docker-compose.yml down
```

`down -v` 会删除验收卷，需在清理记录中再次确认项目名和备份状态后单独执行。

## 5. 阶段 2：首次安装完整主线

Docker 的 profile 选择、镜像构建与静态页面探针继续使用非交互 `ADMIN_UI`；源码首次安装的完整功能验收使用**新的可丢弃 clone + Go `/install` 页面**。单仓库非破坏模式会同时保留 `web-antd`、`web-ele`、`web-naive` 三套源码，选择不修改 tracked 模板；Ant Design Vue、Element Plus、Naive UI 各使用一个独立 clone，避免一个 clone 的本机选择污染另一条用例。

### UAT-INSTALL-001 启动本地依赖和安装器（P）

```bash
# 仓库根目录
MYSQL_PORT=13306 REDIS_PORT=16379 \
  docker compose -f deploy/docker-compose.yml up -d mysql redis

# 普通 API 在未初始化时直接提供 /install、UI 准备与安装 API
cd server
go run ./cmd/api/
```

打开 `http://127.0.0.1:8080/install`。页面必须显示 Ant Design Vue、Element Plus、Naive UI 三个原生单选项。选择 Ant Design Vue 并确认本机选择后，`POST /api/system/install/v1/ui/prepare` 返回 202；页面依次显示 `preflight`、`workspace`、`dependencies`、`complete`。三套 `admin/apps/web-*` 源码、公共业务包和同一份 lockfile 均保持存在，最终 status 为 `ui_prepared`。业务 API 在安装完成前返回 423，health 与安装 API 保持可访问。

### UAT-INSTALL-002 安装向导正向流程（P）

1. 确认页面显示 OS、架构、Node、pnpm、Go 等能力，不泄露环境密钥；缺少 Node 或 pnpm 时 UI 准备按钮保持禁用。
2. 在三套 UI 中选择 `Ant Design Vue`；未勾选本机选择确认时按钮保持禁用。提交后重复点击被阻止，响应和页面不显示命令输出、绝对路径或环境变量。
3. 刷新页面确认 `installing + phase=ui_prepare + selectedUi=antd` 可恢复；继续同一 UI 幂等附着或续跑。完成后“管理界面”为只读 `Ant Design Vue`，运行方式默认=`dev`，默认语言按浏览器建议（安装请求省略语言模式，由服务端默认使用 `single`）；三套源码仍可见。
4. 点“检查目录权限”，确认只展示 `admin/apps/install`、已选 UI 和 `.env` 的保留/写入检查。
5. 数据库填写：MySQL、`127.0.0.1:13306`、Compose 数据库/用户和验收密码；点连接测试。
6. Redis 填写 `127.0.0.1:16379`、DB 0；点连接测试。
7. 初始管理员填写 `UAT-admin` 和 6–72 字符的唯一验收密码；密码仅含 ASCII 英文字母和数字，且至少各 1 个，再次输入确认。
8. 直接开始安装；apply 请求体不得含 `selectedUi`、`confirmCleanup` 或 `confirmReset`，记录每一步、百分比和 `jobId`。
9. 安装完成后确认页面以两个终端卡片明确提示：终端 1 停止并重新启动普通 Go API；终端 2 先运行 `pnpm install` 再运行 `pnpm run dev`，快速开始不要求预先 build。
10. 终端 1 从仓库根目录执行 `cd server`、`go run ./cmd/api/`；终端 2 执行 `cd admin`、`pnpm install`、`pnpm run dev`。
11. 使用旧版已存在、缺少 `VITE_APP_TITLE` 且含自定义端口/API 的本地环境文件执行通用 `dev`；文件字节与自定义值不得被改写，共享运行时应提供标题默认值，页面不得再出现 `%VITE_APP_TITLE%` 警告。
12. `/install` 应显示已安装状态；业务首页替代安装页；再次 apply 或 UI reset 应得到冲突且不重写配置。

核对产物：被忽略的 `admin/.ui-profile.local.json` 只含固定四个字段；`admin/apps/web-antd`、`admin/apps/web-ele`、`admin/apps/web-naive` 均仍在工作区；本机 `.runtime/install/.installed`、`.runtime/install/workspace-dependencies.json`、根目录 `.env` 权限和内容、迁移状态、初始管理员、Super Administrator 角色、通配策略、`must_change_password=true` 均正确。`.runtime/install/workspace-transaction.json` 不得包含密码、DSN 或连接请求原文；切换报告只记录选择、公共层保留和 adapter 复核摘要，不复制密钥或 DSN。

### UAT-INSTALL-003 安装边界和失败恢复（P）

| 输入/操作 | 边界 | 预期 |
|---|---:|---|
| 管理员用户名 | 2 / 3 / 64 / 65 字符 | 3、64 接受；2、65 拒绝 |
| 管理员密码长度 | 5 / 6 / 72 / 73 字符 | 6、72 接受；5、73 拒绝 |
| 管理员密码组成 | 字母+数字 / 纯字母 / 纯数字 / 含符号、空白或非 ASCII 字符 | 仅字母+数字且至少各 1 个接受；其余拒绝 |
| 确认密码 | 与密码不同 | 前端阻止提交，服务端也拒绝 |
| DB/Redis 端口 | 0 / 1 / 65535 / 65536 | 1–65535 进入连接阶段；越界拒绝 |
| DB 密码/DSN | 错误值 | 连接失败信息脱敏，不改变安装状态 |
| Redis 地址 | 空、错误端口、不可达 | 连接检查失败，开始安装按钮保持禁用 |
| 网页 UI | `unknown`、缺值、无确认、准备中改选另一 UI | 前三者 400；改选返回 409，保持原 profile，不二次移动目录 |
| CLI 端口 | 0 / 1 / 65535 / 65536 | 1、65535 接受；0、65536 退出 2，`INIT_ERROR=PORT_INVALID` |
| mode | API 非枚举值 | 400，未执行目录变更 |
| reset | 未安装且有 receipt / fresh clone 无 receipt / 已安装 | 首项网页异步清除本机选择且三模板不动；后两项稳定报错且不删除 profile |
| dev/build（workspace） | pristine / ui_prepared / installed | pristine 退出 2 并输出 `PROFILE_REQUIRED`；ui_prepared 与 installed 均分发到当前 profile package，`.installed` 不作为前端门禁 |
| dev/build（legacy） | ui_prepared / installed | ui_prepared 退出 2 并要求完成旧版网页安装；installed 分发到 profile package |
| 重复提交 | 快速双击或并发 apply | 只产生一个作业；另一请求为冲突 |
| 导航种子冲突 | 预置同 ID、不同字段的菜单或权限 | 事务回滚；页面显示 `navigation_seed_conflict`、`menu|permission` 和安全资源 ID，保留当前输入；不显示 SQL、DSN、密码或驱动原文 |
| 中途失败 | 分别中断 UI 选择、依赖安装、网页 apply | `.runtime/install/workspace-transaction.json` 只记录无敏感信息的 `switching_ui` 或 `dependencies_pending` 阶段；未完成时 dev/build 门禁关闭，以同一 UI 重跑后恢复，三套源码和已选 UI 不丢失 |
| 首次启动残留 | 三模板、profile、marker、事务布局的各类部分组合 | 仅证据充分的状态自动恢复；不覆盖未知文件，不要求用户手动删除隐藏状态 |

恢复还需单独验证 `pnpm run init -- --check --no-open`：它只输出状态和中文下一步，不移动模板、不安装依赖。CLI 事务使用 `owner=admin-init`，服务端事务使用 `owner=server-installer`；双方不得覆盖对方仍在进行的事务。profile、marker、持久化事务或模板布局存在未知冲突时保持现场，并给出稳定状态码。

每次网页安装失败都应保留表单输入并展示失败步骤、原因标识、可用的数据库代码和任务 ID。服务端终端按任务 ID 查找 `installation.job.failed`；结构化日志的资源类型/ID 只接受固定白名单和安全字符，凭据与原始底层错误不得进入响应或日志。

### UAT-INSTALL-004 三种 UI 和两种数据库（C）

- 在三个独立 clone 中分别通过 `/install` 选择 Ant Design Vue、Element Plus、Naive UI，重复 UAT-INSTALL-001/002；准备完成后的只读值、忽略 profile、三套源码和唯一 workspace 必须一致。
- PostgreSQL 使用独立 clone 与 `.runtime/compose/postgres.yaml`，重复连接、迁移、首登和 CRUD 冒烟。
- 安装后的工作树变化必须与预检清单一致；用户预先存在的文件内容应保留或在计划中明确列出。

### UAT-INSTALL-005 已安装克隆切换 UI（P）

前置条件：在同一个 clone 中使用 Ant Design Vue 完成 UAT-INSTALL-001/002，保留原数据库、初始管理员、
根 `.env` 和 `.runtime/install/.installed`。本用例验证 UI 切换是前端选择事务，不是第二次后端安装。

1. 停止管理端开发服务器，记录 `.installed` 的 SHA-256、根 `.env` 去除
   `APP_UI_ACTIVE` 行后的 SHA-256、三个 `admin/apps/web-*` 目录的 tracked diff，以及当前管理员 ID。
2. 在 `admin/` 执行 `pnpm run ui:select -- naive --check`，确认只返回计划；profile、根 `.env`、
   marker、依赖收据和报告的字节均不得变化。
3. 执行 `pnpm run ui:select -- naive`。确认三套源码目录仍存在且 tracked diff 为空；
   `.ui-profile.local.json` 变为 `naive`，根 `.env` 仅 `APP_UI_ACTIVE="naive"` 发生变化，步骤 1
   中排除该键后的摘要保持一致。
4. 再次计算 `.runtime/install/.installed` 摘要，必须与步骤 1 完全相同；
   `.runtime/install/ui-switch-history/` 中新增一个与原 marker 字节一致的审计副本。不得删除或重写
   原 marker，不得生成第二个管理员、角色或数据库安装事务。

## 6. 阶段 3：认证、会话和全局框架

### UAT-AUTH-001 登录、刷新和登出（P）

1. 以初始管理员登录；用户名和邮箱两种标识各测一次。
2. 查看 Network：access token 只用于授权头，refresh token 为 HttpOnly Cookie。
3. 保持页面超过 access TTL（默认 30 分钟）或用可控时钟触发刷新；请求应续期且旧 refresh token 失效。
4. 登出；回退浏览器、刷新页面、重放旧 token，均应进入登录页或得到 401。
5. P0 直接访问任一 `/api/admin/v1/*` 受保护资源，应得到 401。

边界：密码 8/128 字节接受，7/129 字节拒绝；登录只接受用户名或邮箱，手机号登录当前应返回无效凭据。

### UAT-AUTH-002 限流、锁定和验证码（P/C）

- 同一账户连续输错 4 次仍可继续，第 5 次触发默认 15 分钟锁定；正确密码在锁定期也被拒绝。
- 默认每账户/IP 每分钟最多 10 次，超过后返回 429；其他账户不应被连带锁定。
- 验证码启用时，风险阈值默认为 3、窗口 15 分钟、挑战 TTL 2 分钟；验证码只能成功消费一次，过期、重放、服务故障均应失败关闭。
- 错误信息不区分“账号不存在”和“密码错误”，日志不含密码/token。

### UAT-AUTH-003 会话设备（P：API；R：普通 UI）

- 分别用桌面浏览器、隐私窗口、移动浏览器建立会话；默认最多 10 个活动设备。
- 通过会话 API 列表、撤销单设备、撤销其他设备；被撤销端下一请求得到 401。
- **当前红灯**：已有会话 API 客户端但没有普通用户会话管理页面。

### UAT-AUTH-004 注册、找回密码和首次改密（R）

- 注册默认关闭；开启时验证邮箱大小写/空白归一化、同租户唯一、密码 8–128 字节。
- **当前红灯**：注册页、忘记密码页、验证码登录和二维码登录仍是空处理或模板入口。
- **当前红灯**：初始管理员标记 `must_change_password=true`，但个人中心改密按钮只显示成功提示，缺少真实请求和强制改密闭环。

### UAT-SHELL-001 全局框架（P/D）

1. 登录后检查侧栏、面包屑、多标签、全屏、主题、消息、用户菜单、404/403 页。
2. 侧栏严格显示“仪表盘、运维监控、后台权限、系统管理、媒体管理”五组；刷新深层 URL 路由不丢失，无权限菜单不展示，直接 URL 仍由服务端拒绝。
3. `/`、登录完成、404“返回首页”、`/dashboard/analytics`、`/analytics` 与 `/dashboard/workspace` 都收敛到 `/dashboard`，不得经过可见 404。
4. `/dashboard` 显示真实服务摘要或运营数据；没有数据时显示空态，不出现随机访问量、销售额等模板数据。
5. `/iam/me` 返回 `accessCodes` 时不应再请求兼容 `/auth/codes`；模拟旧载荷缺字段时才调用兼容接口。除兼容接口 404 外的失败须回滚本次 token/userInfo/accessCodes，不得形成“页面报登录失败但已有登录态”。
6. `/profile` 与 `vben`/demo 路由只允许在开发模式注册并做视觉冒烟；生产构建不应暴露这些入口，也不纳入生产菜单或业务通过率。

### UAT-MAIL SMTP 账户池与投递记录（P/C/R）

#### 账户配置和连接测试

1. 通过运行时安全渠道准备四个 `SMTP_FIXTURE_ACCOUNT_1..4`，先全部设为 disabled。
2. 逐个新增：账号名称、主机、端口、用户名、权重、密码、发件人邮箱、发件人名称、隐式 TLS。
3. 列表只显示“密码已配置”，编辑其他字段并把密码留空，原密码应保留。
4. 用户名变更且密码留空应拒绝，避免把旧密码绑定到新用户名。
5. 逐个点击“测试连接”：只执行 DNS/TCP/TLS/EHLO/AUTH，邮件记录总数不增加；结果显示阶段、稳定错误和 requestId。
6. 启用账户 1，再逐个启用其余账户；disabled 账户永远不参与发送选择。

边界：名称 1–128；port 1–65535；weight 1–1000000；fromEmail 合法；CR/LF 输入拒绝；同租户 `(account_name)` 和 `(host,port,username)` 冲突，跨租户独立。

TLS：465 保存后使用 implicit TLS；587 保持 implicit TLS 关闭并在服务器声明时 STARTTLS；有凭据但安全连接未建立时应失败关闭。

#### 轮询、加权、失败和发送记录

1. round-robin：四账户权重均为 1，向隔离收件箱发送 8 封，期望顺序循环且 disabled 被跳过。
2. weighted-random：权重设为 `1:2:3:4`，发送足量夹具邮件，记录分布；仅验证明显偏向和每条实际 accountId，不用小样本要求精确比例。
3. 将一个账户设为不可达：当前请求每个候选最多尝试一次，最多 3 次；失败账户进入约 30 秒 cooldown，期间被跳过。
4. 全部禁用或全部失败：API 返回失败，数据库仍有 `failed` 消息记录、attempt 和脱敏错误。
5. 相同 idempotencyKey 连续提交两次，只产生一条消息记录。
6. 列表不含 body；平台管理员受控详情 `includeBody=true` 才显示解密正文；其他角色为 403 或没有 body。
7. 抽查消息记录：有主键、senderId、smtpAccountId、收件人、subject、status、attemptCount、messageId/sentAt、createdAt/updatedAt/deletedAt；正文只以 ciphertext+digest 落库，失败错误不含账号密码。

发送边界：收件人 1–100，重复地址按小写去重；0、101、非法地址、含换行拒绝；subject 1–998；body 最大 10 MiB；正文数据库字段为密文+digest；失败最多 3 次，退避约 1/2/4 秒。

真实 SMTP 用例为 `C`，报告只记录 fixture 代号、阶段和 messageId。**当前红灯**：普通 UI 有账户 CRUD、连接测试和投递记录，没有即时写信/发送入口，也没有正文详情入口；即时发送需通过邮件 API 或认证通知流程补充验收。

### UAT-TASK 任务管理（P/R）

1. 新建 `UAT-task-manual`：type=manual、timezone=UTC、payload schema=`{"type":"object"}`、并发 1、超时 30、重试 3。
2. 编辑、停用、软删除并刷新；同 tenant/org 重名应 409，跨范围不冲突。
3. 新建 cron=`*/5 * * * *`、timezone=`Asia/Shanghai` 的定时任务，观察一个周期。
4. 点立即执行先取消 confirm，再确认；取消时无 run，确认时 POST 返回 202。
5. 相同 idempotencyKey 两次 run，返回同一个 run。
6. pending 时取消，再次取消应状态冲突；failed/dead-letter 时重试，检查 attempt、错误码和日志。
7. A 任务由 B 读取、执行、取消，应为 403/404。

边界：name 1–191；type 仅 manual/http/webhook；payload schema 必须为 JSON object；cron 为支持的 5–7 段；timezone 必须存在；concurrency>=1；timeout>=1；maxAttempts 1–10；policy 仅 allow/forbid/replace；idempotencyKey<=191。

**当前红灯**：worker/scheduler 跟随 API 单进程运行；已注册 handler 只有 import/export。UI 创建的 manual/http/webhook 可完成定义和入队，但通用任务执行会进入 handler-not-found 路径，run 状态闭环也有缺口；多节点 leader/lease 和独立 worker 尚未交付。

### UAT-IMPORT 导入导出（P/R）

1. 下载 CSV/XLSX 模板，核对 MIME、后缀、列名和 XLSX 可打开性。
2. 上传 `name,email` 两行合法文件；预览显示 header、总行数、最多 100 行、SHA-256、过期时间。
3. 提交导入，记录 `previewId/jobId`，观察 pending→running→succeeded/failed。
4. 同 previewId + idempotencyKey 提交两次，只产生一个 job。
5. 含错误行时下载 CSV，列应为 `row,column,code,messageKey`。
6. 导出 preview，检查 allowlist 和敏感列；跨租户读取 job/errors/download 均拒绝。
7. 在合法状态测试取消和重试；不合法状态应冲突。

| 边界 | 输入 | 预期 |
|---|---|---|
| 格式 | CSV、XLSX | 接受 |
| 非法格式 | 伪 XLSX、损坏 zip、未知扩展、MIME 不匹配 | 拒绝，不创建 preview/job |
| 体积 | 50 MiB、50 MiB+1 B | 上限接受；超限 413 |
| 行数 | 1、100000、100001 | 前两项接受；100001 超限 |
| 内容 | 空文件、仅 header、重复 header、未知列、缺必填、坏 email/type | 对应稳定错误；不静默丢列 |
| 预览 | 99、100、101 行 | 页面最多显示 100，totalRows 保持真实值 |
| 过期 | 15 分钟前后 | 过期后 preview/产物链接失效 |

**当前红灯**：UI 固定 `name,email` 且没有通用列映射；导出只处理预览行，页面无完整产物下载闭环；上传/解析读入整文件；preview、payload、artifact 仍有内存状态，重启恢复、真正队列取消/重投、流式 50 MiB、病毒扫描和远程对象存储尚未形成发布级闭环。

### UAT-MONITOR 运维监控（P/C）

1. 默认持有 `ops:server-status:read` 的 PA 打开 `/ops/server-status`（旧 `/system/monitor` 应隐藏重定向），记录实例/build/runtime、CPU 核心与明确命名的 load/进程 CPU、RSS/Go heap/GC、文件系统、DB 状态/延迟/连接池、Redis 状态/延迟/连接池/keyspace、uptime/采集时间；再给非 PA 主体显式授予该访问码，确认同样可访问。
2. 等待 15 秒自动刷新，再点手动刷新；时间更新，页面无闪烁性错误；切到后台标签后暂停轮询，恢复时只发起一次刷新。
3. 缺少 `ops:monitor:read` 的 A1/A-MEMBER 访问页面和 `GET /api/admin/v1/ops/monitor` 应为 403；显式授权主体和超级管理员通配策略应正常放行，不按角色名称硬编码。
4. 检查 DOM/HAR/JSON，不含 DSN、密码、token、原始命令。
5. 仅在可丢弃本地环境，分别暂停 DB、Redis 后刷新：受影响组件显示 degraded/unavailable，其余快照仍返回；恢复服务后页面恢复。
6. 模拟网络离线/500，再恢复并手动刷新；错误态清晰且旧敏感数据不残留。
7. 构造合法零值与采集不可用：零值显示 `0`，不可用显示明确占位，不能因 `omitempty` 或真假值判断混淆；趋势图只标注为“本次浏览会话”。

指标范围是 server 容器/进程视角；宿主机全局指标需要 node-exporter 类外部组件，记为 `C`。

### UAT-UI-001 等价矩阵（P）

每套 UI 至少对登录、仪表盘、用户、角色、菜单、设置、审计、文件、字典、邮件、任务、数据作业、资源监控执行：

3. 一个 401/403 或跨租户用例。

### UAT-UI-002 视口和交互（P）

## 10. 阶段 7：跨模块边界与耐久性

### UAT-X-001 通用字符集和注入边界（P）

对所有名称、描述、主题、文件名字段使用：

- 前后空格、全角字符、Emoji、组合字符、中文/英文混合。
- 单引号、双引号、反斜杠、`<script>`、HTML 实体。
- CR、LF、CRLF、Tab、逗号、CSV 公式前缀 `= + - @`。
- 最小长度、最大长度、最大值+1；空字符串、仅空白、null、缺字段。

预期：按字段规则归一化或拒绝；页面不执行 HTML；响应头无注入；CSV 打开时不执行公式；错误带稳定 code/messageKey/requestId。

### UAT-X-002 并发、幂等和分页（P）

- 两标签同时编辑同资源，验证 expectedVersion 冲突。
- 对支持幂等的 mail/task/import 重放相同 key，数据库只有一个逻辑资源。
- 对列表在新增/删除前后翻页，检查稳定排序、无重复、无越界 pageSize。
- 快速双击提交、刷新确认页、浏览器后退重提，不产生重复副作用。

### UAT-X-003 重启持久性（P/R）

在记录当前状态后重启 server，逐项核对：用户、角色、菜单、系统设置当前值与 revision/status、审计、字典、SMTP 账户、邮件记录、任务定义/run、导入 job、文件列表。

- 数据库持久化资源应恢复，`created_at/updated_at/deleted_at` 语义保持。
- 当前已知红灯：本地文件元数据、导入预览/payload/artifact、部分队列运行态依赖内存，重启恢复预期失败。
- 任何凭据在重启日志中仍应脱敏。

### UAT-X-004 数据库字段通则（P）

抽查每个本版新表：有主键、`created_at`、`updated_at`、`deleted_at`；软删除后默认查询隐藏，唯一索引与软删除复用规则符合当前 schema。邮件账户的租户+账号名唯一，发送记录使用独立幂等键，不按收件人/主题误判重复。
